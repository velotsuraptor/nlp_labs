# IE Policy — Lab4

## Обрані типи полів
- DATE
- LOCATION
- DOC_ID

---

## 1) DATE
### Що вважаємо полем
Дати у форматах:
- dd.mm.yyyy
- dd/mm/yyyy
- dd-mm-yyyy
- dd <місяць_укр> yyyy
- dd <місяць_укр> (без року — raw з parsed_date=None)

### Формат виходу
- якщо дата парситься: YYYY-MM-DD
- якщо рік відсутній або є неоднозначність: raw_value + parsed_date=None

### Що НЕ вважаємо DATE
- версії типу 1.2.3
- десяткові числа 3.14
- просто рік без контексту
- номер повідомлення 123

### Типові edge cases
- 18.04.2024
- 18 квітня 2024
- 18 квітня
- 3.14 не дата
- 1.2.3 не дата

---

## 2) LOCATION
### Що вважаємо полем
Назви міст зі словника українських міст.

### Формат виходу
- canonical city name (як у словнику)

### Що НЕ вважаємо LOCATION
- прикметники від міст (львівський, харківська)
- загальні слова типу “місто”
- випадкові збіги з іншими словами

### Типові edge cases
- м. Львів
- Харків
- Чернівці
- Львівська область (не витягувати як місто, якщо правило exact match)
- Суми як місто vs інші контексти

---

## 3) DOC_ID
### Що вважаємо полем
Номери документів/звернень/повідомлень/заяв у контекстах:
- №123
- повідомлення 123
- заява №45
- документ №77
- звернення №456

### Формат виходу
- id_type=DOC_ID
- value=<digits>

### Що НЕ вважаємо DOC_ID
- рік сам по собі
- просто число без контексту
- дати
- відсотки

### Типові edge cases
- повідомлення 123
- заява №45
- №2024 (може бути рік — precision-first, краще пропустити частину таких)
- 100% не DOC_ID
- 18.04.2024 не DOC_ID
